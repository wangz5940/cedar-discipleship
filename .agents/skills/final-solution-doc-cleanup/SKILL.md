# 项目文档定稿规范

文档应让未参与讨论的读者直接理解最终方案、实际变化和必要操作，不依赖会话历史。

## 适用范围

用于方案定稿、需求调整后的文档更新，以及提交或发布前的说明整理。按本次任务限定文件范围，不借文档清理改动无关内容或产品行为。

历史记录、决策记录和实施跟踪文档可以保留与其用途相关的过程；不得为了简洁删除必要的审计证据或未完成事项。

## 内容规则

- 直接写最终规则、接口、流程和用户可感知的变化；优先使用明确、可执行的正向表述。
- 删除被否决的方案、临时折中、讨论经过、过期的现状与目标比较，以及已失效的 TODO 或阶段状态。
- 直接删除过时内容，不留下删除标记、划线、隐藏注释、废弃字段或禁用示例作为替代。
- 只说明本次实际变化。通常不罗列未修改的功能、恢复过的尝试或“仍然保留”的日常行为；仅在影响评估、兼容验证或操作安全确有需要时说明相关边界。
- 保留实现、使用、维护和验收所需的身份、权限、数据契约、失败处理、安全、兼容、迁移与回滚约束。否定表述仅在准确界定这些边界时保留。
- 验证说明记录实际入口、操作、结果和未覆盖项，区分自动化测试、模拟环境与真实部署；不得把计划执行写成已通过。
- 同一概念使用统一术语。枚举和支持范围以权威定义为准，不将示例配置误写成完整支持清单。
- PR 描述说明最终问题、改动、必要影响和验证结果；临时审批、等待合入及发布进度在任务对话中说明。
- 更新日志记录日期、变更引用与实际影响，遵守仓库格式，不写会话过程或原始提交流水。

## 整理方法

1. 根据最新确认的要求与权威实现确定最终内容；遇到未确认的行为或 PR 冲突，遵守仓库人工确认规则。
2. 检查范围内正文、表格、图示、示例、注释和引用，重点查找旧方案名、旧字段、TODO、待确认、尚未、暂不、方案一／二、废弃和删除标记。
3. 区分每处匹配：有效约束保留并写清，必要迁移保留操作步骤，过程或过时内容直接删除；关键词本身不能作为批量删除依据。
4. 同步受影响示例、术语和链接，保持改动集中；不复制个人路径、私有环境、凭据或临时证据到公共文档。
5. 复查全文及差异，确认内容与实际行为一致、引用有效、必要边界完整，且没有通过隐藏内容留下旧方案。

## 完成标准

- 读者可直接理解最终要求、变化和必要操作。
- 正文、示例与引用使用一致术语并符合实际行为。
- 讨论过程与失效状态已清理，必要历史及审计信息仍符合文档用途。
- 未覆盖项如实列出；范围内没有个人环境信息和临时文件。
