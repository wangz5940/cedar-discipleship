# 香柏木 · UI 重设计执行方案

交付对象：Antigravity｜范围：`antifronted` 全站桌面、手机、平板、弹层｜日期：2026-09-20

## 1. 设计决策

采用「雪松绿、暖白底、编辑式排版」的统一语言。产品核心是每日学习、打卡和小组协作：让用户一眼找到今天要做的事，让管理者迅速读懂数据。视觉关键词为安静、可靠、清晰、有温度。

配套 `cedar-ui-preview.html` 是可交互的方向样稿，包含今日学习、统计、资料、管理和弹窗；其中内容和数字均为演示数据，不连接业务接口。它定义视觉关系，不代表业务功能已经实现，也不要求把样稿的 HTML 直接搬进 Vue。

### 代码审查发现（未进行已登录网站的运行态审查）

- `src/main.js` 实际加载 `styles.css`、`tokens.css`、`base.css` 和 `layout.css`；历史的 `antd-theme.css` 与 `redesign.css` 未被入口引用，已在重构收尾时移除。
- `AppRoot.vue` 使用 Ant 风格深色侧栏、自写表单、内联布局；业务组件仍大量使用原有类名。`styles.css` 超过 4,000 行，主题文件存在大量 `!important`，继续末尾叠加 CSS 会增加冲突。
- `SiteDialog.vue`、成员月历、`ContentViewer.vue`、`ResourceGovernance.vue` 的弹窗各自维护外壳。统一标题、操作区、遮罩、滚动与键盘行为，不能只换圆角。
- 手机底栏遍历全部 `navItems`，另加退出入口；应固定高频入口，把退出和管理收进个人/更多菜单，保留原权限判定。
- 资料卡片有 `minmax(320px, 1fr)` 内联网格，手机在容器有内边距时可能溢出；需要实际宽度测试。
- `CheckinWorkbench`、`Dashboard`、`MinistryGroups` 使用 Teleport 挂到 AppRoot 的占位节点；不能在改版时随意移除挂载 ID。阅读页还有独立启动路径。

### 字体、空间和形状

- UI 字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。不依赖外部字体下载。
- 品牌开场标题允许使用宋体栈：`"Noto Serif SC", "Songti SC", SimSun, serif`；只用于登录页和今日学习的短标题，不用于后台表格。
- 页面标题桌面 28/38、手机 24/34；区块标题 18/28；正文桌面 14/22、手机 16/26；元信息 12/18，手机重要说明至少 14px；数据 30/36，数字启用 `tabular-nums`。
- 间距只用 4、8、12、16、24、32、48。页面内边距桌面 32、平板 24、手机 16；卡片桌面 24、手机 16。
- 控件圆角 8px、卡片 16px、弹窗 20px；标签仅小型状态使用胶囊形。不要所有元素都使用大胶囊。
- 控件桌面高 40px，手机 48px；图标点击区最少 44×44px。单行输入手机字号至少 16px。
- 图标统一 `@lucide/vue`，20px、描边 1.75；导航 22px。迁移已有 Ant 图标，保留 Ant 组件内置图标，无需替换其内部结构。
- hover 只改背景/边框，按钮不跳动；动画 160–220ms，遵循 reduced-motion。

## 3. 页面与导航

### 应用外壳

桌面 ≥1200px：232px 浅色侧栏 + 64px 顶栏；内容最大宽 1440px 居中。侧栏品牌「香柏木 / 门训学习」，主要入口沿用已有 tab key：今日学习、小组统计、小组与服事、资料库；有权限才出现管理。底部账户区含身份、下载中心、退出。品牌名可由现有配置替换，不修改站点业务标识。

平板 768–1199px：72px 图标侧栏，有可访问名称及 tooltip；侧栏允许展开覆盖内容。首页的辅助栏降到主列表下方。

手机 <768px：56px 顶栏，左侧品牌/当前页，右侧小组切换和账户。底栏固定 5 项「学习、统计、小组、资料、更多」，更多打开含管理、下载、账户、退出的菜单，并按权限过滤。所有已有功能必须仍可到达。底栏高度 `64px + env(safe-area-inset-bottom)`，正文提供对应底部留白；阅读、全屏表单覆盖底栏。不要全站 `overflow-x:hidden` 来掩盖布局错误。

小组切换统一为顶栏单一入口，菜单内展示当前小组、其他小组、设为默认；切换后同步页面内容与抬头。保留加载/失败反馈和原状态更新流程。

### 今日任务的设计细节

任务行分为：40px 类别图标、任务名称与内容摘要、状态、操作。名称层级高于类别。阅读/播放操作与打卡按钮分开，避免打开内容就触发打卡。完成态使用勾选图标与“已打卡”，仅淡化背景，不把正文变为低对比灰。

所有任务数量、类别、日期及标题从现有 store 获取；不要照样稿写死四项。保留未来日期限制、历史日期、撤销打卡和失败回滚。文案准确区分“已阅读”“已打卡”，不得用阅读行为自动推断完成。

右侧只使用已有可获得的信息，例如所选小组、任务分项、当月统计；不凭空增加连续打卡、阅读时长或推荐引擎字段。样稿中的内容标题仅用于展示排版。

## 4. 统一全部窗口

统一的是材质、结构和行为，按任务复杂度保留合适尺寸。新增 `components/ui/AppOverlay.vue` 封装现有 Ant Modal/Drawer 能力或等效成熟实现，业务组件只提供内容与操作。通过适配层继续支持 `ui/dialog` 的调用与返回语义。

| 类型 | 桌面 | 手机 | 覆盖功能 |
|---|---|---|---|
| 确认/提示 | 居中 440px | 居中，左右 20px，最大 440px | 提示、删除、打卡撤销等 |
| 简短表单 | 居中 560px | 内容较短可底部面板，最长 85dvh | 重命名、创建、日期选择 |
| 复杂编辑 | 右侧 640px 抽屉 | 全屏 | 权限、批量共享、资源配置 |
| 阅读预览 | 宽 min(1120px, 视口减64px)，高≤90dvh | 全屏 | 文章、图片、视频、PDF |
| 成员月历 | 居中 560px | 底部面板，月份完整可见 | 月历、日期筛选 |
| 下载 | 右侧 420px 抽屉 | 全屏 | 下载中心 |

结构固定：标题区（标题+简短说明+关闭）／可滚动内容区／操作区。标题区桌面最少 64px、手机 56px；内边距桌面 24px、手机 16px。按钮桌面右对齐，“取消”在前、主动作在后；手机两个按钮等分，长文案改上下排列。危险动作只用具体“删除 3 个资源”等名称，不用含糊“确定”。

行为要求：

1. 弹窗打开后移动焦点，Tab 限制在最上层弹窗内，关闭恢复到触发元素。`aria-labelledby` 关联标题，描述可选 `aria-describedby`。
2. Escape 只关闭最上层；有未保存内容时先确认放弃。提交进行中禁止重复提交，并定义是否允许关闭；不能关闭后误显示成功。
3. 遮罩 `rgb(22 34 27 / 38%)`，默认无大面积 blur。只读预览可点遮罩关闭；危险确认/未保存表单不以误触遮罩直接丢弃。
4. 锁定背景滚动并补偿滚动条宽度；嵌套弹窗关闭不能提前恢复背景滚动。浮层统一挂到应用级容器。
5. `max-height` 使用 `dvh`，内容单独滚动，顶部标题和底部按钮始终可达；手机键盘打开后输入框和提交区不被挡住。
6. 层级统一：基础 0、sticky 20、下拉 100、遮罩 1000、面板 1010、嵌套确认 1100、消息 1200。避免组件自行写 99999。
7. Toast 成功短提示 3 秒；失败不只 toast，表单内持久显示错误和可行重试；上传、下载、加载分别有真实状态。

## 5. 实施结构与边界

保持 Vue 3 + Pinia + Ant Design Vue，不为视觉改版迁移框架。按现有 Ant Design Vue 4.x 的类型定义配置 `ConfigProvider` 主题，将 primary、字体、圆角等映射到同一套 token；CSS 变量和组件 token 共用一个来源，禁止两套颜色手工同步。

建议新增：

```text
src/styles/tokens.css          # 唯一设计变量
src/styles/base.css            # reset、排版、可访问焦点
src/styles/layout.css          # 页面、断点、安全区
src/components/ui/AppPage.vue
src/components/ui/AppPanel.vue
src/components/ui/AppToolbar.vue
src/components/ui/AppStatus.vue
src/components/ui/AppEmpty.vue
src/components/ui/AppOverlay.vue
src/components/ui/AppMobileNav.vue
```

Button/Input/Select/Table 优先使用已有 Ant 组件并统一 theme；只封装产品语义，不另造一套基础控件库。业务组件负责数据和动作，公共组件负责外观、间距与基础交互。

迁移期间可将旧变量映射到新 token；先替换组件再删旧规则。禁止直接删整个 `styles.css`，禁止追加另一个总覆盖文件，禁止依赖全局 `button`、`input` 强覆盖 Ant 内部结构。内联布局逐步改为 scoped class；主题特殊覆盖集中且有注释。

必须保留：认证、角色权限、小组切换、所有 tab key、Teleport 目标、阅读 URL 参数、API 参数和响应语义、任务计算口径、日期限制、上传下载、批量操作和已有导入导出。可以拆分大模板，不借此次设计更换 store、后端接口或统计规则。

## 6. Antigravity 执行顺序

1. **基线盘点**：记录当前工作区修改，读取项目约束；列出各角色页面、所有弹窗触发入口。记录登录/主页面/手机/弹层截图和当前 `typecheck`、`test`、`build` 结果，区分原有失败。确认真实 navItems 和窗口清单，不只覆盖样稿展示的功能。
2. **设计底座**：建立 token、ConfigProvider、公共布局/状态/弹层组件。先制作可浏览的组件页，展示按钮、输入、标签、卡片、空态、错误态和四种弹层。
3. **完整样板**：完成登录、应用外壳、今日学习、确认窗口；用 390px 和 1440px 截图与样稿校准颜色、字体、空间、布局。进入真实状态验证，禁止仅交静态首页。
4. **业务扩展**：迁移统计、资料、阅读、下载、小组页面及其内部窗口。保留各页特有结构，共用视觉规则。
5. **管理闭环**：迁移学习配置、周任务、资源治理、目录、机器人、考勤和全部批量窗口。确认每项旧功能仍可访问。
6. **清理和交付**：移除已无引用旧样式；运行项目现有检查；完成端到端核心流程和视觉矩阵；给出修改文件、前后截图、验证结果与尚存问题。

## 7. 验收清单

- 视口：360×800、390×844、430×932、768×1024、1024×768、1440×900、1920×1080；另测手机横屏和桌面 200% 缩放。
- 每个页面和每类窗口包含正常、加载、空、失败、长标题状态；表单包含必填错误、提交中和成功。
- 360px 无页面级横向溢出；表格/PDF 可在明确容器内横滚；底栏不挡住最后一条内容；安全区和键盘下按钮可达。
- 普通文字对比度至少 4.5:1，大字和关键非文本控件至少 3:1；焦点可见；状态不只靠颜色。逐项测 token 实际组合。
- 普通成员、组管理员、超级管理员分别核对导航与权限；隐藏入口不能成为唯一权限校验。
- 核心路径：登录 → 切组 → 日期切换 → 阅读 → 打卡/撤销 → 查看统计/月历；资源预览/下载；编辑保存/失败重试；共享、批量导入/删除（使用测试数据）；退出。
- 保留数据刷新与导航状态；列表翻页、搜索、返回后的状态不因改样式丢失。
- 键盘可操作菜单、任务、弹窗；Escape/焦点陷阱/焦点恢复与背景滚动正常；读屏能够识别按钮和窗口标题。
- 视觉验收：所有页来自同一套颜色、字体、控件和窗口；无旧蓝色按钮、深蓝侧栏、玻璃大圆角弹窗零散残留。图表分类色、图片和媒体内容不受此限制。
- 运行 `npm run typecheck`、`npm test`、`npm run build`；新增测试只覆盖有风险的改动，如窗口焦点、移动导航权限、打卡事件不误触。不要写只检查 class 名的镜像测试。
