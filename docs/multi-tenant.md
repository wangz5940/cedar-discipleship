# 多小家数据与权限

系统采用一个账号可加入多个小家、一次选择一个学习小组的模型。每个学习小组只属于一个小家；现有学习小组在迁移时归入 ID 为 `1` 的“原有小家”。用户身份仍由全局 `users` 表承载，小家关系与小家角色存于 `tenant_members`，小组关系继续存于 `group_members`。

权限从上到下为：平台超级管理员、小家管理员、小组管理员/组长、普通成员。超级管理员可访问所有小家；小家管理员是独立创建的虚拟账号，可管理所属小家的所有小组，不进入小组打卡成员名单；普通成员只可进入实际加入的小组。普通账号可以同时属于多个小家，所选小组决定当前小家上下文。每次请求从数据库重新加载所属关系和角色，成员关系或权限变更后，旧访问令牌不能继续获得原权限。

普通学习小组不再提供设置或取消组长的入口；已有 `group_leader` 身份仍保留原有权限。专项小组的组长设置属于独立机制。

小家管理员通过“小家管理”维护小家内的小组并查看管理员，通过“人员管理”维护普通成员；其他管理界面处理小家内各组的学习内容、资源和记录。只有超级管理员可以创建小家、设置小家管理员账号密码、修改管理员名称与密码、调整已有小组所属小家，以及管理跨小家的全局账号与机器人配置。修改管理员密码后，该账号的现有登录会话失效。账号密码是全局身份属性；修改小组默认密码时，不会重置同时属于多个小家的账号密码，以免影响其在其他小家的登录。

新资源的跨组分享与导入仅允许同小家的小组；已共享资源查询及备份中新建资源引用也验证来源和目标小家一致。小组转移小家后，已导入的资源引用在来源分享仍有效时可继续阅读，未导入的跨小家资料不再显示或允许导入。媒体播放链接要求当前有效登录会话且会话已选择对应小组，避免链接流转到其他小家后仍可播放。小家管理员和成员仅能看到可进入小家的小组；超级管理员可查看全部小组。

部署时按正常迁移顺序执行 `015_tenants.sql`。迁移会创建原有小家，将旧小组归入其中，并按有效小组成员关系补齐小家成员；迁移可重复执行。超级管理员创建小家时只填写名称，之后可创建新小组或调整已有小组所属小家，并独立创建小家管理员账号。人员管理负责普通成员的增减，小家管理不提供将现有人员提升为管理员或移出小家的接口。
