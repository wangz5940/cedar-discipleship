# 多主体数据与权限

系统采用一个账号可加入多个主体、一次选择一个学习小组的模型。每个学习小组只属于一个主体；现有学习小组在迁移时归入 ID 为 `1` 的“原有主体”。用户身份仍由全局 `users` 表承载，主体关系与主体角色存于 `tenant_members`，小组关系继续存于 `group_members`。

权限从上到下为：平台超级管理员、主体管理员、小组管理员/组长、普通成员。超级管理员可访问所有主体；主体管理员可管理所属主体的所有小组，即使未逐组加入；普通成员只可进入实际加入的小组。一个账号可以同时属于多个主体，所选小组决定当前主体上下文。每次请求从数据库重新加载所属关系和角色，移出主体或降权后，旧访问令牌不能继续获得原权限。

主体管理员通过“主体管理”维护主体内的小组、成员和管理员，通过现有管理界面处理主体内各组的学习内容、成员、资源和记录。只有超级管理员可以创建主体、把已有全局账号首次加入某个主体，以及管理跨主体的全局账号与机器人配置。账号密码是全局身份属性；修改小组默认密码时，不会重置同时属于多个主体的账号密码，以免影响其在其他主体的登录。

跨组资源共享仅允许同主体的小组。导入、已共享资源查询及备份中的资源引用都再次验证来源和目标主体一致。媒体播放链接要求当前有效登录会话且会话已选择对应小组，避免链接流转到其他主体后仍可播放。主体管理员和成员仅能看到可进入主体的小组；超级管理员可查看全部小组。

部署时按正常迁移顺序执行 `015_tenants.sql`。迁移会创建原有主体，将旧小组归入其中，并按有效小组成员关系补齐主体成员；迁移可重复执行。首次新增主体由超级管理员创建，创建时同步生成首个小组，并可指定一位已有账号为首位主体管理员。主体成员移除后保留原小组历史数据，但其访问权限立即失效；重新加入主体后，原有小组成员关系可恢复使用。
