# 多主体数据与权限

系统采用一个账号可加入多个主体、一次选择一个学习小组的模型。每个学习小组只属于一个主体；现有学习小组在迁移时归入 ID 为 `1` 的“原有主体”。用户身份仍由全局 `users` 表承载，主体关系与主体角色存于 `tenant_members`，小组关系继续存于 `group_members`。

权限从上到下为：平台超级管理员、主体管理员、小组管理员/组长、普通成员。超级管理员可访问所有主体；主体管理员是独立创建的虚拟账号，可管理所属主体的所有小组，不进入小组打卡成员名单；普通成员只可进入实际加入的小组。普通账号可以同时属于多个主体，所选小组决定当前主体上下文。每次请求从数据库重新加载所属关系和角色，成员关系或权限变更后，旧访问令牌不能继续获得原权限。

主体管理员通过“主体管理”维护主体内的小组并查看管理员，通过“人员管理”维护普通成员；其他管理界面处理主体内各组的学习内容、资源和记录。只有超级管理员可以创建主体、独立创建主体管理员账号、将已有小组加入指定主体，以及管理跨主体的全局账号与机器人配置。账号密码是全局身份属性；修改小组默认密码时，不会重置同时属于多个主体的账号密码，以免影响其在其他主体的登录。

跨组资源共享仅允许同主体的小组。导入、已共享资源查询及备份中的资源引用都再次验证来源和目标主体一致。媒体播放链接要求当前有效登录会话且会话已选择对应小组，避免链接流转到其他主体后仍可播放。主体管理员和成员仅能看到可进入主体的小组；超级管理员可查看全部小组。

部署时按正常迁移顺序执行 `015_tenants.sql`。迁移会创建原有主体，将旧小组归入其中，并按有效小组成员关系补齐主体成员；迁移可重复执行。超级管理员创建主体时只填写名称，之后可创建新小组或将已有小组加入主体，并独立创建主体管理员账号。人员管理负责普通成员的增减，主体管理不提供将现有人员提升为管理员或移出主体的接口。
