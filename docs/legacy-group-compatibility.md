# 旧小组程序兼容性

## 核验范围

2026-09-20 核验 `/volume2/docker` 下四个 `*-checkin` 原程序的配置、源码、资料目录和记录格式。三个运行容器中的 `index.html`、`server.js` 与宿主机源码一致（统一换行符后比较）。`zw1-checkin` 没有运行容器，以目录源码和配置为依据。

| 原程序 | 容器 | 周配置数量 | 每日内容 | 周内容及签到 |
| --- | --- | ---: | --- | --- |
| `zk-checkin` | `zk-checkin` | 15 | 《旷野的筵席》，中文日期标题 | `weekly_task.md` 按书卷主题提取；逐读物、视频、背经；提纲及分享 |
| `zw1-checkin` | 无运行实例 | 53 | 《永活之泉》日期模式；顶层 `daily_reading` 每日两章 | 14章外部读物目录；一次“周任务”签到；视频、背经；PDF/MP4/MP3分享 |
| `zwlingyi-checkin` | `zwkeswick-checkin` | 24 | 《永活之泉》日期模式；同一每日两章序列 | 仅展示每周两个主题，关闭读物和视频入口，保留“周任务”及背经签到 |
| `zwmouss-checkin` | `zw-checkin` | 14 | 《永活之泉》日期模式；每日灵修、每日读经独立签到 | 周内容集中展示，独立“周任务”签到；中文记录字段 |

生产 Cedar 中已确认的映射为 `zw1 → group_id=3`、`zk → group_id=4`。`agape-a` 有独立且已调整的学习计划，不能仅凭内容相似认定为 `zwmouss`，也不能覆盖其计划。当前数据库没有以 `zwlingyi`、`zwmouss` 命名的小组。

## 需要统一支持的行为

### 每日内容

- 数字 Markdown 标题（如 `# 187`）按起始日期和篇号选择。
- 中文日期支持纯文本、Markdown 前缀、日期后附文章标题；例如 `七月六日`、`### 九月二十日 信心的能力`。
- `mode=date` 按月日查找；`mode=numbered` 按篇号查找；`mode=auto` 先尝试篇号再尝试日期。不得用同文件中的无关数字标题覆盖日期选择。
- 日期标题兼容“廿、卅”等旧式写法，以及日期紧接在上一篇末尾的原文件格式错误。
- 正文必须在下一篇处停止，不能混入相邻日期、卷首语或整本书。
- 保留 `schedule_history` 的生效日期语义。
- 旧顶层 `daily_reading` 必须转换为规范的读经起点、书卷序列和每日章数。
- 序列允许跨书卷；最后一天只剩一章时保留该章，耗尽后隐藏入口。
- `zwmouss` 只有独立“每日读经”签到，没有每日读经内容排程；不得因此生成默认书卷或章节。

`zw1`、`zwlingyi` 的真实读经样本：

| 日期 | 预期章节 |
| --- | --- |
| 2026-05-10 / 2026-05-11 | 撒母耳记下24、列王纪上1 |
| 2026-05-12 | 列王纪上2、3 |
| 2026-05-22 | 列王纪上22、列王纪下1 |
| 2026-09-20 | 诗篇77、78 |
| 2027-08-03 | 启示录22 |
| 2027-08-04 | 无读经入口 |

### 周内容与资料入口

- 显式 `readings[].url/type` 和 `weekly_reading_catalog` 中的外部 HTML 页面保持可读，不转换成不存在的本地下载文件。
- 没有显式 URL、原程序使用 `weekly.reading_path` 的读物，保留文档来源和章节定位；不以标题模糊匹配猜测 PDF。
- `zk` 的“复习马可”定位到马可章节，2026-09-14周定位到使徒行传章节。实际文档以 `##` 分章，正文在下一 `##` 之前结束。
- `zwmouss` 的 `openWeeklyReading` 虽存在于源码，但没有正常页面调用，其“永活之泉”周标题也不匹配 `weekly_task.md`；实际需要保留的是周资料浏览入口。
- 本地资源来源依 `mounted_files` 和配置引用识别，包含 `MP3`、`MP4`、根目录 Markdown、讲义、提纲、分享资料。
- `class_rep_shares` 的全局分享独立于周视频开关，保留 PDF、音频、视频类型和原始编码路径。
- 内联背经原文安全转义；只有经文引用而无原文时，保留原程序按经文引用打开圣经的入口。
- 已配置的视频外链不能在迁移时丢失；属于已核实本地挂载的地址转换为本组资产，真正外链保持原地址。
- 未配置内容的空视频、空背经占位不生成必做任务。
- 配套资料优先采用明确绑定，不能在无匹配时任意打开列表第一项。

### 完成语义

- 活动周统一按逐读物完成；旧“周任务”记录仅作为历史数据保留，不能当成所有书籍页码已读，也不再生成新的整周任务。
- 旧聚合周中的读物恢复为逐项任务；`book_enabled=false` 时不展示读物入口。
- 独立每日灵修、每日读经保留独立完成身份；其他小组维持原有合并模式。
- 记录解析支持英文字段和 `zwmouss` 的中文字段，识别 `done`、`已完成`；`已撤回` 不计完成。
- 迁移记录需解析本组、本周内明确的任务身份；存在歧义时报告，不能猜测并制造资源继承。
- 首页、统计、成员日历、通知使用同一完成语义。

## 已确认的实现缺口

基线提交 `38783ca`：

1. `migrate-json.oldConfig` 丢弃顶层 `daily_reading`、`weekly_reading_catalog`、`class_rep_shares`。
2. `normalizeTaskSections` 提前删除本地灵修路径，使文件迁移阶段失去原始引用。
3. `migrate-resource-files` 的固定扫描清单遗漏 `MP3`、`MP4`、`Yonghuo.md`。
4. 前端日期标题精确匹配不识别《永活之泉》的“日期 + 文章标题”。
5. 前端读经计算固定每天一章，没有消费两章序列。
6. 周读物入口忽略任务的直接外链；默认 Markdown 读物缺少来源和章节提取。
7. 仅支持非空背经正文入口，没有引用到圣经页面的回退。
8. 周任务聚合模式、独立每日签到没有对应完成模型。
9. 迁移仅识别英文 `done`，所有插入记录的 `task_id` 固定为空。
10. 空视频/背经在迁移时被补成任务；HTTP 视频链接未保存为可读内容。

## 统一实现

- 每日完成方式由 `task_sections.daily.checkin_mode` 控制：`combined` 保持合并签到，`separate` 生成 `daily_devotion` 和 `daily_scripture` 两个独立任务。
- 活动周仅生成 `weekly_book` 等逐项任务；历史 `weekly_checkin` 任务和记录继续用于审计、统计与兼容导入，但不再返回为可操作任务或接受新打卡。
- 顶层 `daily_reading` 被规范化为带书卷 ID、章数和 `chapters_per_day` 的完整序列；读完最后一章后不再循环。
- 迁移保留 `weekly_reading_catalog`、`class_rep_shares`、原始 Markdown 路径和外部 HTTP(S) 地址。
- 资源发现覆盖 `MP3`、`MP4`、`Yonghuo.md`，本地文件仍按 SHA-256 与字节大小判重。
- 中文记录字段映射到明确任务身份；`已完成` 有效，`已撤回` 无效，歧义周任务拒绝导入并进入报告。

生产抽查还确认：

- `zk` 的15个书籍任务全部没有资产绑定；其 `weekly_task.md` 已存在为资产422。
- `zw1` 的14个旧 HTML 资产仍以外部地址存储，没有活动 binding；需要还原为显式内容链接。
- `zw1` 有45个未绑定资源的视频任务，其中大量来自空配置占位。
- `zw1` 当前每日灵修路径为空，且原目录本身缺少 `Yonghuo.md`。代码兼容不能替代缺失原文件；不得擅自复制其他组文件。

## 验证与发布边界

- 每组使用脱敏配置与最小内容片段建立回归样本；源全文、个人签到和凭据不进入仓库。
- 对实际存在的日期文档运行全年章节边界验证，对完整读经序列验证起点、跨卷和终点。
- 文件唯一性仍由 SHA-256 与字节长度判断，跨组导入遵守授权。
- 保留禁止未来签到、已有签到周任务强制修改保护、事务锁和跨组隔离。
- 视频按 `asset_id` 继承；书籍按 `asset_id + 页码` 继承。
- 已迁移数据只作可审计的定向修复，保留当前任务、组状态和管理员修改；不执行整组强制覆盖。
- 不自动创建尚未迁入的小组，不修改四个原程序，不清理其资料。
- 本地构建后上传 NAS 组装镜像，只重建受影响服务。
