# 主屏幕安装与系统通知

安卓统一使用站内消息，在网站前台逐条显示顶部横幅，每条 4 秒后收起并记为已读；静音抑制展示。安卓不申请系统通知权限、不创建推送订阅。苹果保留原系统推送。

添加到主屏幕和系统通知授权是两个独立操作。网站不显示独立“安装与通知”卡片，不在开屏弹出浏览器能力说明。

## 使用步骤

1. 从 HTTPS 地址登录。
2. 在浏览器菜单选择“安装应用”或“添加到主屏幕”。
3. 安卓从自己的成员卡片切换站内提醒／静音，不出现系统授权弹窗；苹果从主屏幕打开后点击“允许通知”，在原生弹窗授权。
4. 苹果只有设备订阅及服务器绑定成功后才提示开启完成；安卓打开页面接收站内横幅，收起后记为已读。
5. 苹果退出到桌面验证锁屏通知及点击关闭；安卓在网站前台验证横幅及 4 秒自动收起，网页关闭或后台时不承诺通知。

## 浏览器适配边界

| 浏览器 | 主屏幕安装 | 提醒方式 |
| --- | --- | --- |
| Chrome / Edge 安卓版 | 浏览器菜单 | 站内横幅，不使用系统推送 |
| Firefox 安卓版 | 浏览器菜单 | 站内横幅，不使用系统推送 |
| Samsung Internet 安卓版 | 浏览器菜单 | 站内横幅，不使用系统推送 |
| 小米 / 华为 / UC 等安卓浏览器 | 浏览器菜单 | 站内横幅，不使用系统推送 |
| Safari iOS / iPadOS | 分享菜单添加到主屏幕 | 从主屏幕打开后，由用户点击调用系统授权；保留既有推送流程 |

通知授权、配置读取、后台服务启动、设备订阅和服务器绑定分别报告失败阶段。设备订阅失败可能涉及浏览器推送服务或网络，不能仅凭授权成功断定后台推送可用。网站不集成厂商原生 App 推送 SDK，也不能绕过浏览器缺失的接口或受限网络。

清单沿用原应用 ID、启动地址与范围；安装服务不缓存账号页面或 API 响应。拒绝授权或绑定失败不会改动静音或历史学习记录。苹果不同浏览器、设备分别授权和订阅；安卓静音沿用账号小组偏好。

## 验证范围

自动化覆盖原生安装事件、菜单回退、独立窗口识别、能力缺失、订阅失败和绑定重试；这些不是安卓手机真机结果。各浏览器实际安装、锁屏推送、通知权限和通知点击仍需按上述步骤在设备上验证。

- 苹果解除静音时记录当前提醒边界，仅推送随后新建的提醒；安卓站内积压提醒保留。点击苹果任一学习通知会关闭本应用已显示的其余学习通知并持久化设备去重，其他设备仍只关闭当前通知。通知栏清除不等于批量修改历史提醒的已读状态。
